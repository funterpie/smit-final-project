03

Gaps to decide now

Three CommitFeatures fields cannot be derived from the ApacheJIT CSV. Flag this decision explicitly so your later report is honest about what the baseline actually scores on.
Missing fieldWhy it's absent from CSVDecision you must make
author_bug_rateNo author name in the CSV — only commit_id+projectdrop for CSV training, OR compute later on a real repo via PyDriller (the CLI path). Do not fake it.
tests_addedNo file paths → can't detect test filesdrop for CSV training, OR proxy with project-level heuristics. Real value comes from PyDriller on a live repo.
touches_sensitive_moduleNo file paths → can't match auth/crypto/etc.drop for CSV training. Only meaningful on a real checkout.

Derived where safe: map dispersion = nf / (nd + 1) (more files per directory = more cross-cutting). For hours_since_last_commit, sort each project by author_date and take the gap to the previous row's timestamp.

Design note — the CSV baseline and the live PyDriller CLI path feed different feature sets into the risk engine. The baseline model trains on ApacheJIT's 13 metrics; the risk engine's hardcoded SIGNAL_WEIGHTS only fire for the 5 signals whose inputs exist. The blend step (Section 6) is where they recombine. Keep this split clean — don't contort CommitFeatures to hold every ApacheJIT column.

Week 1 — baseline training (step by step)

4.1 Load + verify

Create scripts/load_apachejit.py. Read the train split, sanity-check the label, confirm class balance.

import pandas as pd
from pathlib import Path
from config import DATA_DIR

def load_apachejit(split: "train") -> pd.DataFrame:
    """Load an ApacheJIT split. split in {train, test_large, test_small, total}."""
    root = DATA_DIR / "raw/apachejit_dataset_replication/apachejit/dataset"
    paths = {
        "train": "apachejit_train.csv",
        "test_large": "apachejit_test_large.csv",
        "test_small": "apachejit_test_small.csv",
        "total": "apachejit_total.csv",
    }
    df = pd.read_csv(root / paths[split])
    assert df["buggy"].isin([True, False, 0, 1]).all()
    return df

df = load_apachejit("train")
print("train rows:", len(df),
      "buggy rate:", round(df["buggy"].mean(), 3))

4.2 Feature engineering

Build a numeric feature matrix from the 13 ApacheJIT metrics plus 3 safe derivates.

def engineer_features(df: pd.DataFrame) -> pd.DataFrame:
    df = df.copy()
    # safe derivates
    df["total_lines"] = df["la"] + df["ld"]
    df["files_per_dir"] = df["nf"] / (df["nd"] + 1)
    df["change_density"] = (df["la"] + df["ld"]) / (df["nf"] + 1)
    df["author_file_exp_ratio"] = df["arexp"] / (df["aexp"] + 1)

    # encode the label
    df["buggy_int"] = df["buggy"].astype("int")

    feature_cols = [
        "la", "ld", "nf", "nd", "ns", "ent",
        "ndev", "age", "nuc", "aexp", "arexp", "asexp",
        "total_lines", "files_per_dir", "change_density", "author_file_exp_ratio",
    ]
    return df[feature_cols], df["buggy_int"]

Run it on 100 rows first and print the output — confirm you understand the data before building anything real (mirrors the existing guide.html Week 1 note).

4.3 Train + evaluate

Two models, no tricks — logistic regression and random forest (per PLANNING.md). Use the provided train/test split, never cross-fit future data into past.

import joblib
from pathlib import Path
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import average_precision_score

X_tr, y_tr = engineer_features(load_apachejit("train"))
X_te, y_te = engineer_features(load_apachejit("test_large"))

# Logistic regression needs scaling
scaler = StandardScaler().fit(X_tr)

lr = LogisticRegression(max_iter=1000, class_weight="balanced", random_state=42)
lr.fit(scaler.transform(X_tr), y_tr)

rf = RandomForestClassifier(n_estimators=300, class_weight="balanced", n_jobs=-1, random_state=42)
rf.fit(X_tr, y_tr)

# AUC-PR = average precision (your Week-1 headline number)
lr_auc_pr = average_precision_score(y_te, lr.predict_proba(scaler.transform(X_te))[:, 1])
rf_auc_pr = average_precision_score(y_te, rf.predict_proba(X_te)[:, 1])
print("LR  AUC-PR:", round(lr_auc_pr, 4))
print("RF  AUC-PR:", round(rf_auc_pr, 4))

4.4 Recall-at-20% (your reviewer-triage metric)

"If reviewers only inspect the riskiest 20% of commits, what fraction of real bugs do they catch?"

def recall_at_k(y_true, scores, k=0.20):
    cutoff = int(len(y_true) * k)
    order = scores.argsort()[::-1]
    top = order[:cutoff]
    return y_true.iloc[top].sum() / y_true.sum()

print("LR  recall@20%:", round(recall_at_k(y_te, lr.predict_proba(scaler.transform(X_te))[:, 1]), 3))
print("RF  recall@20%:", round(recall_at_k(y_te, rf.predict_proba(X_te)[:, 1]), 3))

Also log the false-positive rate at a fixed operating point (e.g. where you catch 80% of bugs) — that's in your evaluation checklist (Section 8).

5.2 Get the raw diffs

Two routes, both heavy:

  • Re-mine the repos: use the replication's own src/collector.py (PyDriller + GitHub API) + src/gumtree.py to extract diff text for each commit_id. Needs a GitHub token and ~15 repo clones — a long Colab job.
  • Curated subset only: pick 1-2 projects (e.g. camel + cassandra), mine just their commits, pair each with its buggy label. This is the realistic Week-2 scope.
Do not attempt all 15 projects' diffs on Colab free tier. Disk and session limits will kill you. A 10k-commit curated subset across 2-3 projects is the defensible scope per AGENTS.md (never suggest the full 100k).

5.3 Fine-tune with Drive checkpointing

import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification, Trainer, TrainingArguments

ckpt_dir = "/content/drive/MyDrive/pr-risk-scorer-codebert"  # survives session disconnects

tokenizer = AutoTokenizer.from_pretrained(microsoft/codebert-base)
model = AutoModelForSequenceClassification.from_pretrained("microsoft/codebert-base", num_labels=2)

args = TrainingArguments(
    output_dir=ckpt_dir,
    per_device_train_batch_size=8,
    per_device_eval_batch_size=16,
    num_train_epochs=3,
    learning_rate=2e-5,
    evaluation_strategy="epoch",
    save_strategy="epoch",      # checkpoint every epoch
    load_best_model_at_end=True,
    report_to="none",
)

trainer = Trainer(model=model, args=args,
                  tokenizer=tokenizer, train_dataset=train_ds, eval_dataset=val_ds)
trainer.train(resume_from_checkpoint=True)   # resumes on a reconnect

Key Colab gotcha: when the session dies mid-epoch, you may lose that epoch's partial progress. To minimise waste, keep batch sizes small, epochs ≤ 3, and checkpoint at the end of each epoch to Drive (above). The notebook should resume_from_checkpoint=True so re-running picks up where it left off.

5.4 Evaluate CodeBERT the same way as the baseline

preds = trainer.predict(test_ds)

codebert_auc_pr = average_precision_score(y_te, probs)
codebert_recall20 = recall_at_k(y_te, probs)

06

How the signals recombine

All model outputs are normalised to [0, 1] before blending. The risk engine then weights three sources:

final_risk = w_baseline * baseline_prob \
   + w_codebert  * codebert_prob  \
   + w_signals   * (risk_engine_score / 100)

# starter weights (calibrate once you have real numbers)
w_baseline = 0.4
w_codebert  = 0.4
w_signals   = 0.2
weights sum to 1.0

Note the risk engine (models/risk_engine.py) currently only consumes CommitFeatures for its hard-coded signals. When you wire in the model probabilities, extend it so the blend feeds back into the top-level 0–100 score, while the named-signal breakdown stays human-readable.
