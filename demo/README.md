# PR Risk Scorer demo cases

These examples are synthetic, newly written code changes. The runner copies each
case into a temporary Git repository, creates a real local commit, and sends that
commit through the project's `prscore review` CLI and configured scoring models.
The cases are not ApacheJIT observations and are not evaluation data.

- `low`: small parser change with tests; expected to trigger few risk signals.
- `medium`: small payment capture validation change without tests; the payment
  path and missing tests are visible risk signals.
- `high`: cross-cutting session security change in four sensitive modules without
  tests; the sample diff exceeds 300 changed lines.
- `no-close-match`: same real low-risk commit reviewed with the RAG threshold set
  to 0.9999 to demonstrate that a below-threshold neighbor is omitted.

All reviews are written to an isolated demo SQLite file. The Groq key is cleared
by the runner so explanations use the local fallback. Set
`PRSCORER_DEMO_DB=/path/to/demo.db` to choose a different demo database. RAG uses
the configured local index and cached embedding model; when those are missing,
the CLI reports no match and still returns a score and explanation.

Run from the project root with `./demo/run_demo.sh`. Outputs in `outputs/` are
regenerated by the actual CLI, and the dashboard uses the same database when the
API is started with `AUDIT_DB_PATH=demo/demo.db`.
