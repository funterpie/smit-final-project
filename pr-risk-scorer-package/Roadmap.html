WEEK 1

Data & baseline

~14 hrs
DayTask
1–2Download ApacheJIT, explore it, understand the label column and commit structure.
3Build feature extraction with PyDriller/GitPython: diff size, files touched, author bug-history, test presence.
4–5Train logistic regression + random forest baseline. Get a first AUC-PR number.
6Write the weighted risk engine (named signals, fixed weights) on top of baseline features.
7Buffer / catch-up day.
Checkpoint: a script that takes a commit and prints a risk score with signal breakdown. No deep learning yet — this alone is a working, demoable core.
WEEK 2

CodeBERT model

~14 hrs
DayTask
1–2Set up CodeBERT fine-tuning on Google Colab free tier. Free tier disconnects after idle time or ~12hrs — save a checkpoint to Google Drive every epoch so a disconnect never means starting over.
3–4Train on a subset of ApacheJIT (tens of thousands, not the full 100k+) — free Colab sessions are too short and unreliable for a full run. A smaller, well-chosen subset still gives a valid comparison against the baseline.
5Blend CodeBERT score into the weighted engine alongside handcrafted signals.
6Compare CodeBERT vs. baseline on AUC-PR + recall-at-20%. This comparison is your core research contribution.
7Buffer / catch-up day.
Checkpoint: a saved, working CodeBERT model that beats the baseline on paper, with numbers written down.
WEEK 3

Explain layer, CLI, packaging

~16 hrs
DayTask
1Sanity-check RAG first, throwaway script: embed ~500 sample bug-inducing commits with a code-aware embedding model, query it, confirm matches make sense.
2Build the real RAG index (curated subset only) with FAISS or version-pinned ChromaDB, plus the similarity threshold.
3Wire the LLM explanation call (Groq free tier) with the local-fallback path if the API fails.
4Build the CLI (prscore review) and the git pre-commit/pre-push hook.
5PyInstaller build locally on Ubuntu, confirm it runs clean — this is your one guaranteed-working OS.
6GitHub Actions build matrix for Windows + macOS. Since there's no physical Mac/Windows machine to test on, add a smoke-test step inside the CI job itself — run prscore review <fixture-diff> right on the runner after building, so a passing CI run is real proof it works, not just that it compiled.
7Buffer / catch-up day — packaging always eats more time than expected.
Checkpoint: a packaged binary that scores a diff, shows signals, shows evidence (or "no match found"), and prints an explanation — running on at least 2 of 3 OSes.
WEEK 4

Dashboard, evaluation, report

~14 hrs
DayTask
1–2React + TypeScript dashboard — score list, review card, Approve/Request Changes/Escalate, reading from the SQLite audit log. Cut this first if behind schedule.
3Run the full evaluation: AUC-PR, recall-at-20%, false-positive rate, plus a small human-rated check on explanation quality.
4–5Write the report: problem, methodology, dataset, architecture, evaluation results, limitations.
6Rehearse the demo — pick 2–3 real diffs that show different risk levels clearly.
7Final buffer.
Checkpoint: a demo, a written report with real numbers, and packaged binaries — the non-negotiable deliverables all present.
Cut order if time runs short, bottom first: Dashboard → RAG evidence → LLM explanation → (never cut) weighted score + CLI + baseline/CodeBERT comparison.

Deadline is soft — if week 3–4 results look strong, ask for the extension rather than rushing the report. If behind schedule by end of week 2, cut the dashboard immediately rather than waiting until week 4.
