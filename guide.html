01

Set up the repo

Create the folder structureUse the layout in AGENTS.md — data/, features/, models/, rag/, explain/, cli/, dashboard/, api/, eval/, notebooks/. Doesn't need to be perfect on day one, just start with the top-level folders.
Drop these four .md files + this guide in the repo rootSo any AI coding tool you open (Claude Code, Cursor, etc.) reads AGENTS.md automatically and has the full context.
Create the Claude ProjectPaste the project instructions block into the Project's custom instructions, and upload these five files as project knowledge.
02

Week 1 — first thing to actually build

  1. Download ApacheJIT (link it in RESOURCES.md once you've found the current repo)
  2. Write a throwaway script that loads 100 commits and prints their labels — confirm you understand the data before building anything real
  3. Build the feature extraction function: takes a commit, returns diff size, files touched, author bug-history, test presence
  4. Train the baseline logistic regression, get a first AUC-PR number — this is your Week 1 checkpoint
Don't skip ahead to CodeBERT or RAG yet. The baseline working end-to-end is what makes every later step demoable, even if nothing else gets finished.
03

Using the docs day-to-day

  • Starting a coding session? Open PLANNING.md, find this week's tasks, work top to bottom.
  • Explaining the project to sir or a teammate? Pull from IDEA.md — it already has the "why not just Claude/Gemini" answer written out.
  • Asking an AI assistant for code? It should already read AGENTS.md if it's in the repo root — if it suggests something AGENTS.md explicitly says not to do, point it back to that file.
  • Forgot which library does what? RESOURCES.md has the full stack table.
04

The one rule that matters most

If you're behind schedule at any point, cut in this order and never reorder it:

Dashboard → RAG evidence → LLM explanation → (never cut) weighted score + CLI + baseline/CodeBERT comparison

The core score and comparison is the actual research contribution and the non-negotiable deliverable. Everything else is presentation on top of it.
