My five project ideas, in plain words

Each idea below says what it does, shows a small picture of what goes in and what comes out, and explains how you would prove it works.

  • TextileGuardFinds defects in fabric photos
  • TurboTrendSays when a machine will break
  • PR Risk ScorerWarns when a code change is risky
  • VoiceGradeTells you which English sounds to fix
  • GridGuardFinds electricity meters that look suspicious

TextileGuard

You upload a photo of fabric. It shows you where the defects are.

Build risk: mediumBest demo
compares it with normal fabric
How it works
The model looks at many photos of good fabric and learns what normal looks like. Anything that does not match normal gets highlighted. You do not need thousands of photos of broken fabric.
Real-life example
A worker at a small textile mill takes a photo of a cloth roll. The app draws a red glow on a snag the eye can easily miss.
Who uses it
Small textile factories that want automatic quality checks but cannot label thousands of defect images.
What you build
PatchCore and PaDiM models, plus a simple autoencoder to compare against. A web page where you upload an image and see the heat-map.
How you prove it works
How often it correctly calls an image good or bad (ROC-AUC), and how well the red area matches the real defect (pixel AUROC).
Watch out
The MVTec AD dataset has texture classes (carpet, leather, tile, and others) but no true fabric class. Say this clearly in the report. It is also for academic use only, not for selling.

TurboTrend

It reads a machine's sensors and tells you how long it has left and when to service it.

Build risk: lowCleanest report
predicts the future
How it works
It learns from machines that were run until they broke. Then it looks at a new machine's sensors and guesses how many working cycles are left. It also says how sure it is, and picks the cheapest time to do maintenance.
Real-life example
"This engine has about 40 cycles left, give or take 8. Book service within 30 cycles."
Who uses it
Factory and maintenance teams who want to fix machines before they fail, but not too early.
What you build
An LSTM or 1D-CNN model that predicts remaining life, with a method that gives a range (deep ensembles or MC-dropout). A scheduler that compares repair costs. A dashboard.
How you prove it works
Prediction error (RMSE), the NASA score (which punishes late warnings more), how often the true value falls inside your range, and money saved by the schedule.
Watch out
The data is NASA's simulated jet engines, so there is no Pakistani angle. The strength here is the careful evaluation, not local relevance.

PR Risk Scorer

It reads a code change and warns you: "risky, get a senior to check this."

Build risk: mediumNo overlap in the batch
checks size, history and the code itself
How it works
It learns from old code changes that later caused bugs. It looks at how big the change is, how many files it touches, and how the code itself reads. Then it gives a new change a risk score.
Real-life example
A junior developer changes the payment code in many files at once. The tool marks it high risk so a senior looks before it is merged.
Who uses it
Software teams with many junior developers, where seniors do not have time to read everything.
What you build
A simple logistic regression model as the baseline, and a CodeBERT model that reads the code. A web page where you paste a change and get a score.
How you prove it works
AUC, and one easy question: if seniors only review the riskiest 20 percent of changes, how many of the real bugs do they catch?
Data
ApacheJIT, a public set of Apache project commits labelled by whether they caused bugs.

VoiceGrade

You say an English sentence. It shows which sounds you got wrong and how to fix them.

Build risk: mediumHighest ceiling
splits it into sounds and scores each one
How it works
The model lines up your voice with the sounds it expected to hear. It then checks how close each sound is to correct speech, and turns that into scores like a teacher would give.
Real-life example
You say "weather". The app says the "th" sounded like a "d", and tells you to put your tongue between your teeth.
Who uses it
Job seekers preparing for interviews, and call-centre trainees. Human trainers cannot give this feedback to everyone.
What you build
A wav2vec2 model to align speech to sounds, a Goodness-of-Pronunciation score, and a small model that predicts expert scores. A web page where you record and see results.
How you prove it works
How closely your scores match the scores human experts gave (Pearson and Spearman correlation), and how well it spots wrong sounds (phoneme-level AUC).
Data
speechocean762, a free set of 5,000 English sentences from non-native speakers, each with expert pronunciation scores.
Watch out
The alignment tools can be fiddly to set up. Test them in week 1.

GridGuard

It looks at home electricity use and lists which meters look suspicious, so inspectors visit those first.

Build risk: mediumHonest about fake labels
learns normal use, flags strange use
How it works
The model learns what normal electricity use looks like. When a meter's use does not match the normal pattern, it gets a high suspicion score. The meters are then sorted from most to least suspicious.
Real-life example
One house's use suddenly falls by more than half while the neighbours' use stays the same. That meter moves to the top of the list.
Who uses it
Electricity distribution companies that lose money to theft and only inspect meters at random today.
What you build
An autoencoder that learns normal use, plus a gradient boosting model, and a ranking page for inspectors.
How you prove it works
The main question is: if a crew can visit only 100 houses, how many of them really had a problem (precision at k)? You also report PR-AUC.
Watch out
No public data has real theft labels, so you add fake theft cases yourself and say so in the report. Also, the UCI household dataset is only one house, so use a multi-home dataset such as Pecan Street or build simulated homes.

Words you will see

Anomaly: something that does not look normal.

Model: the program that learns from data and makes predictions.

Baseline: a simple model you compare your model against, to show yours is better.

Dataset: the collection of examples the model learns from.

If you can only pick one

Pick TextileGuard if you want a demo people understand in five seconds and a strong local story.

Pick TurboTrend if you want the safest build and the cleanest evaluation for the report.
